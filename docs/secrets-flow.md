# Secrets Flow — Source of Truth & Transport

## Principle

**HashiCorp Vault (HV) is the single source of truth for all runtime
secrets.** Ansible-Vault (AV) is a transport mechanism — it carries
secrets from HV into playbook execution. AV files are ephemeral
derivatives; HV is authoritative.

```
┌─────────────────────┐
│  HashiCorp Vault    │  ← SOURCE OF TRUTH
│  (runtime secrets)  │
└─────────┬───────────┘
          │
          │ sync-hv-to-av.sh (one-time, operator-driven)
          │ reads from HV, writes AV-encrypted file
          │
          ▼
┌─────────────────────┐
│  ansible-vault      │  ← TRANSPORT (ephemeral derivative)
│  vault/staging/     │
│  secrets.yml        │
└─────────┬───────────┘
          │
          │ ansible-playbook --ask-vault-pass
          │ or AV password from HV
          │
          ▼
┌─────────────────────┐
│  Playbook execution │
│  secrets injected   │
│  into hosts         │
└─────────────────────┘
```

## What Lives Where

| Secret | HashiCorp Vault | Ansible-Vault | Notes |
|--------|----------------|---------------|-------|
| DB password | `secret/data/jolarca/staging/db_password` | `vault_pg_app_password` | Generated by CSPRNG |
| Django SECRET_KEY | `secret/data/jolarca/staging/django_secret_key` | `vault_django_secret_key` | 64 bytes |
| Redis password | `secret/data/jolarca/staging/redis_password` | `vault_redis_password` | Generated by CSPRNG |
| MinIO access keys | `secret/data/jolarca/staging/minio_*` | `vault_minio_*` | Generated by CSPRNG |
| Stripe test keys | `secret/data/jolarca/staging/stripe_*` | `vault_stripe_*` | `sk_test_*` / `pk_test_*` ONLY |
| Grafana admin pw | `secret/data/jolarca/monitoring/grafana/admin_password` | — | Read directly by Grafana |
| AV password | `secret/data/jolarca/ops/ansible-vault-password` | — | Ops policy only |

## Ansible-Vault Password Retrieval

**Option chosen:** AV password stored in HV at
`secret/data/jolarca/ops/ansible-vault-password`, retrievable only by
the `ops` policy.

At playbook execution time:

```bash
# Operator retrieves AV password from HV
export ANSIBLE_VAULT_PASSWORD=$(vault kv get -field=password \
  secret/jolarca/ops/ansible-vault-password)

# Run playbook with vault password from environment
echo "$ANSIBLE_VAULT_PASSWORD" | ansible-playbook \
  playbooks/65-app.yml \
  -i inventories/staging/hosts.yml \
  --vault-password-file /dev/stdin

# Unset immediately after
unset ANSIBLE_VAULT_PASSWORD
```

**Alternative (rejected):** Operator enters AV password manually
(`--ask-vault-pass`). Rejected because it requires the operator to
know a second secret. HV as the single source is cleaner.

## Sync Script

`scripts/sync-hv-to-av.sh` reads from HV and writes the AV file.
It uses a short-lived HV token that is revoked after the sync.

## Security Controls

1. **No secret values in git** — enforced by .gitignore, Gitleaks
   (pre-commit + CI), and `scripts/audit-no-secrets.sh`
2. **AV file is gitignored** — `ansible/inventories/**/artifacts/`
   is in .gitignore
3. **HV audit log** — every secret read is logged
4. **Least-privilege policies** — app can only read `secret/data/jolarca/staging/*`
5. **Stripe LIVE keys NEVER enter the system** — only `sk_test_*` / `pk_test_*`
